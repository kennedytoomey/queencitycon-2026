08 · Trend 02 · Automation
CI/CD vulnerabilities

Common CI/CD Vulnerabilities

Pwn request

A workflow uses a risky trigger with elevated privileges, handing out repo write permissions or access to secrets.

Seen in the wild: s1ngularity
Injections

A workflow passes data through shell commands, left unvalidated and vulnerable to remote code execution.

Seen in the wild: hackerbot-claw
Compromised credentials

A maintainer token or publishing credential is stolen, and the trusted action itself starts shipping malicious releases.

Seen in the wild: Trivy, KICS

12 · Trend 02 · Automation
A tag is a pointer, not a version

GitHub Action Versioning

# pinning to a tag
uses: thollander/actions-comment-pull-request@v2
  • A tag is a pointer, not a version. Anyone with write access to the action's repo can move the tag to new code. Your workflow follows it silently.
  • You can't answer "what ran?" No pinned hash means no record of the code that touched your secrets last Tuesday.
  • Updates arrive without review. A maintainer change, a compromised account, a new transitive dependency, all shipped straight into your runner.

15 · The Fix · Dependency Cooldowns
A simple waiting period dramatically reduces risk

Implementing Dependency Cooldowns

01
Delay
Don't install a release the moment it's published.
02
Review
Give the community and scanners time to catch it.
03
Reduce exposure
Skip the window when most malicious packages live.

Turn it on today

Dependabot
updates:
  - package-ecosystem: npm
    cooldown:
      default-days: 7
npm
# .npmrc
min-release-age=7
yarn
# .yarnrc.yml
npmMinimalAgeGate: "7d"

18 · Platform
Platform changes

GitHub Is Making Changes

Initial compromise
Limiting trust
  • actions/checkout prevents checking out untrusted code from forks
  • New policies limit who triggers risky actions and which triggers are permitted
  • Actions cache is read-only for untrusted triggers
Exfiltrating credentials
Actions network firewall
  • A new network firewall (preview) logs all outbound traffic to detect malicious behavior
Propagating the attack
Barriers to expansion
  • Dependabot has a default dependency cooldown of 3 days
  • Potentially malicious workflows are held for approval
  • Workflow-level dependency locking
  • Immutable releases
Incident response
Easier token rotation
  • Self-service credential revocation
  • Expanded credential revocation API support

19 · Takeaways
Three things, in this order

Audit What You Implicitly Trust

Take inventory. What are you currently trusting?
Easy wins first. Add cooldowns, pin versions, then widen scope.
Make it repeatable. Add checks and document trust decisions.
Not the lesson
Software is inherently insecure.
The lesson
Audit what you implicitly trust.

If your strategy assumes your supply chain is trustworthy,

attackers are already ahead.
